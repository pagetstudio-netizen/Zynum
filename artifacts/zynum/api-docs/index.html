Documentation de l’API ZyNum v1

L’API ZyNum permet aux applications serveur de parcourir le catalogue, acheter un numéro virtuel, consulter les SMS reçus et gérer les commandes avec le solde du compte.

URL de base : https://zynum.net/api

Authentification de l’API ZyNum

Les endpoints privés acceptent la clé API du compte dans Authorization: Bearer zyn_…. La clé se consulte dans Profil > Développeur. Conservez-la uniquement sur un serveur de confiance, jamais dans le code du navigateur, les logs ou un dépôt public.

Endpoints de l’API v1

MéthodeCheminUsage
GET/v1/servicesCatalogue public des services.
GET/v1/countries?service=telegramPays, prix et disponibilité indicative.
GET/v1/operators?service=…&country=…Opérateurs et prix pour un service et un pays.
GET/v1/balanceSolde USD du compte.
POST/v1/buyAcheter un numéro. Le corps JSON exige service et country.
GET/v1/check/{orderId}Consulter le statut et le SMS d’une commande du compte.
GET/v1/orders?page=1&limit=20Historique paginé des commandes du compte.
POST/v1/cancel/{orderId}Annuler une commande admissible et demander son remboursement.
POST/v1/finish/{orderId}Terminer une commande après réception d’un SMS.

Une réponse de succès à l’achat contient order.id. Utilisez cet identifiant ZyNum (pas la référence du fournisseur) pour consulter, annuler ou terminer la commande. Les prix et la disponibilité sont des instantanés, pas une réservation.

Suivi des commandes et remboursements

Appelez GET /v1/check/{orderId} pour consulter l’état et les champs smsCode et smsText. Une annulation manuelle est disponible tant que la commande est PENDING, ou RECEIVED sans code SMS. Le solde est recrédité uniquement après confirmation du fournisseur. Un remboursement en attente n’est pas un crédit confirmé.

Webhooks sortants ZyNum

Configurez une seule URL HTTPS publique dans Profil > Développeur. ZyNum envoie order.created à la création d’une commande et order.updated quand son statut public ou ses données SMS changent. Le corps contient type, createdAt et data.order, avec les champs de commande de l’API, notamment smsCode et smsText.

Les headers incluent X-ZyNum-Event, X-ZyNum-Delivery (identifiant stable de livraison) et X-ZyNum-Signature au format sha256=<hex>. La signature est un HMAC-SHA256 du corps brut exact, calculé avec la clé API unique du compte. Vérifiez-la côté serveur avant de traiter le SMS. 

const expected = "sha256=" + createHmac(
  "sha256",
  process.env.ZYNUM_API_KEY,
).update(rawRequestBody).digest("hex");

Répondez avec un statut HTTP 2xx pour confirmer la réception. Les erreurs réseau, HTTP 408, 425, 429 et 5xx sont réessayées avec un délai exponentiel, jusqu’à 12 tentatives. Les autres réponses hors 2xx sont considérées définitives. La livraison est « au moins une fois » : dédupliquez avec X-ZyNum-Delivery. Modifier ou désactiver l’URL arrête les livraisons en attente vers l’ancienne destination.

Statuts de commande et réponses d’erreur

Les statuts publics sont PENDING, RECEIVED, FINISHED, TIMEOUT, BANNED et CANCELED. Les erreurs HTTP courantes sont 400 pour une entrée ou un achat refusé, 401 pour une authentification invalide, 404 pour une ressource introuvable, 409 pour un état incompatible, 502 si la fin de commande n’est pas confirmée et 503 si l’annulation ou le remboursement reste en attente.

La documentation interactive et les exemples détaillés sont chargés par l’application ZyNum.
